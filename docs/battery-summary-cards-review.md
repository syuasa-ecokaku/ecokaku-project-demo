# 蓄電池：全7部門のサマリー2カード統一

## 変更範囲

`index.html` のiframe内にある、蓄電池のサマリー2カードだけを共通化。対象は不動産・電力申請・営業・法務・購買・工事・メンテナンス。太陽光／データセンターは既存のカード描画を継続する。案件・業務項目・状態・予定・期限のデータは変更していない。

開始時：`feat/battery-shared-ten-case-data`、HEAD `6dd6154`。接続先は指定リポジトリ、追跡ファイルの未コミット変更なし、AGENTS.mdは検出されず。既存の未追跡 `.agents/` は保持。作業ブランチ：`feat/battery-summary-card-standard`。

## 共通コンポーネント

- `StatusCountCard`：工程／ステータス名を左、件数を右に置く行形式。件数だけをリンク風の操作にし、従来の絞り込み処理へ渡す。ボタン型のステータスラベル・ヘッダー帯を廃止。
- `UpcomingScheduleCard`：日付→案件名→予定項目の行形式。日付はYYYY-MM-DD、案件名は青色リンク。内部の案件IDを使って従来の詳細へ遷移。長い名前は省略＋titleで全文表示、名前がなければ番号、予定がなければ「直近の予定はありません」。
- `.dept-summary-*`：共通CSS。PCで等幅2カラム、白背景、青系の薄い枠、角丸、濃紺・太字見出し、Meiryo、46pxの行と区切り線。狭幅では縦並び。
- 部門別のデータを各コンポーネントへ渡し、部門専用のカードデザインを増やしていない。

## 集計・予定の維持

| 部門 | 件数 | 予定 |
| --- | --- | --- |
| 不動産 | 既存の取得ステータス | 既存の土地契約予定・対応期限 |
| 電力申請 | 既存の6工程・`powerStage` | 従来の受電／供給開始の予定・実績 |
| 営業 | 既存の商談・提案・契約状態 | 既存の商談・提案・契約予定・対応期限 |
| 法務 | 既存の契約確認・承認・締結状態 | 既存の対応期限 |
| 購買 | 既存の発注・納品状態 | 既存の納品予定・仕入支払期限・対応期限 |
| 工事 | 既存の施工状態 | 既存の完工・検査・引渡し予定・対応期限 |
| メンテナンス | 既存の保守・対応状態 | 既存の点検予定・対応期限 |

- 電力申請の検索・担当者・工程・設備による集計範囲、対象外判定、工程順を維持。予定も従来の4項目（88、supplyDesired、89、supplyStart）から取得し、実績を含む旨を補足。
- 他6部門は従来どおり事業全体の保存済みデータを集計。予定は部門設定の項目と基準日条件を維持。日付昇順・最大6件も変えていない。
- 見積、申請／回答予定など、今回の分類例だけを根拠に新しい状態・予定項目は追加していない。
- 0件の表示は既存の選択肢定義＋既存の登録状態を利用。選択肢自体は変更せず、絞り込み欄にも既存の0件の状態を表示し、選択表示と実際の条件がずれないようにした。
- KPI、案件番号、ケース名、予定日、期限、詳細遷移、保存・取消は既存処理を維持。
