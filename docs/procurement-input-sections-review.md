# 購買：業務順の入力区分

2026-11-11。公開済みの購買モック（`646355d`）に追加。5タブと既存の親ページlocalStorage保存を維持し、変更は購買モジュール内に限定。

## 追加した画面

発注管理→発注詳細の「入力区分」セレクトと直接移動ボタンで切り替える。他部門の入力区分セレクト・保存バー・入力枠のスタイルを利用。

| 入力区分 | 内容・操作 |
| --- | --- |
| ① 購入内容・発注準備 | 事業（参照）、購入区分、仕入先、担当者、備考、複数明細の製品/型番・数量/単位・案件・在庫/費用区分。案件は明細ごとに指定 |
| ② 発注・納期確認 | ①の同じ明細を引継ぎ、単価・税・金額、発注番号/日、納品予定・方法・場所・予定荷受人・配送・支払条件を設定。明示的な「発注を確定／変更を反映」 |
| ③ 納品・荷受確認 | 同じ明細に複数回の分納を登録。発注・累計受領・取消・未納の数量、実荷受人、不足/破損の確認内容、実績と備考。倉庫受領は同じ入庫実績 |
| ④ 在庫・引当・出庫 | 共通在庫と当該発注由来の数量を分けて表示。使用予定、引当、出庫日/数/担当者、履歴と元入庫・発注明細の追跡。直送は倉庫対象外 |
| ⑤ 請求確認・支払予定 | 既存タブと同じ請求・複数支払予定・条件生成・請求紐づけ・差額。納品前の前払も操作可 |
| 随時：移管・変更 | 既存移管の申請/一覧への入口、①②の変更への移動、理由付き未納取消、変更理由・変更前後の履歴、未対応範囲 |

「前へ」「下書きを保存」「保存して次へ」と、直接移動を用意。順番を強制する完了ゲートはない。発注未確定の明細への受領、数量不足の引当・出庫・移管など、整合性に必要な検証は操作時に行う。

## 下書きと状態

新規発注は①から開始し、明細や必須項目が未入力でも下書きとして保存できる。下書きバッファは `procurement.inputDrafts[orderId]`、明細のキーは明細ID。確定台帳は既存の `orders/lines` で、②の確定・変更反映時に同じ内部IDへ適用する。下書きの製品・数量は①から②へ引き継ぎ、再入力は不要。未確定の入力は実在庫・未納発注残・発注確定金額へ加算しない。

区分・発注・事業を切り替えても編集中の値はバッファに保持。「下書きを保存」「保存して次へ」では購買の他区分・他事業の下書きも含め、同じブラウザー・URLの保存領域へ保存する。保存後は再読込で復元する。保存しないまま再読込した編集は復元対象外。

入力状況は業務状態と別。区分ごとに「未入力／入力途中／確認済／対象外」を表示する。「確認済」は必要情報を満たした上で担当者が専用操作をした場合のみ。対象データの署名を保存し、値や関連実績が変われば入力途中へ戻る。直送のみ・倉庫対象確定明細なしの④は対象外。③の既存荷受情報がない実績は「未記録」とし、予定荷受人から推定して確認済にしない。

業務状態は既存の未納・一部納品・完了などを実績から算出し、新規発注には「発注下書き」を追加。入力区分の確認済は発注確定・支払済を意味しない。

## 入出庫の追跡

既存の管理単位を増殖させず、引当・出庫・移管に `sources: [{receiptId, qty}]` を追加。`receiptId → receipts.lineId → lines.orderId` で元発注へ遡る。

- 受領は一度だけ `receipts` に登録。倉庫・直送・費用を同じ既存区分で扱い、別の入庫台帳を作らない。
- 在庫は既存の実績計算を維持し、製品・事業・保管場所で共通化。④には共通の実在庫/引当/利用可能と、この発注由来の使用可能残/引当残/利用可能を併記。この発注分の欄は使用不可数量を除く。
- 共通一覧からの引当はFIFOで元入庫を紐づける。発注詳細の「この発注分を引き当てる」はその発注の入庫だけを対象にする。
- 出庫は引当の元入庫を引継ぎ、数量と引当残を同時に更新。担当者も独立して記録。
- 案件間/倉庫間移管は同じ元入庫IDを引き継ぎ、移動先でも当該発注の④へ表示。全社在庫と支払予定を増やさず、二重反映を防止する。
- 履歴から元の発注④へ、入出庫一覧から関連発注③④へ、請求・支払一覧から⑤へ移動できる。移管詳細から同製品を扱う発注の参照候補、在庫履歴、元/先案件を開ける。完了移管の数量に対応する発注は `sources` で特定する。

## 仮設定と未対応

FIFOによる元入庫の選択は仮設定。旧モックの実績は元入庫対応を持たないため、旧受領・出庫・完了移管の順に追跡情報を推定し、履歴に「仮設定：既存実績のFIFO推定」と表示する。数量や実績日は改変しない。推定不能な製品の追加引当・移管は停止し、対応修正は今回未対応と明示する。

発注済内容の変更と未納取消は理由を必須とし、`changeHistory` に対象発注ID・時刻・理由・変更前後を保存。納品または取消実績のある明細は製品・案件・区分・単位・納品方法・場所を固定。数量を受領済＋取消済未満へ変更できない。支払予定は発注変更や取消で自動精算せず、⑤の差額を確認して明示的に更新する。

受領・出庫・完了移管実績の訂正/削除、返品、使用不可品の復旧/廃棄、価格変更に伴う請求書自動訂正、前払精算は未対応。画面に範囲を表示する。経理の支払確定・支払実績、サーバー共有、ファイル本体保管は追加しない。既存の税端数・代表支払条件・暦日計算の仮設定も維持する。

## 5ケースの確認手順

1. **案件向け・複数商品・送料・分納**：`DEMO-BATTERY-001`の①で明細別案件とパネル・PCS・送料を確認→②の同じ明細・金額・納期を確認→③でパネルを分納。累計/未納と在庫一覧へ反映。送料の役務完了は在庫に加算しない。
2. **案件未指定の在庫購入**：「発注する」→①で在庫向け、仕入先・担当者・製品・数量を入力し案件は未指定→保存して②へ→単価・発注番号/日・倉庫を入力し確定→③で荷受人と不足/破損確認を含めて受領。①の明細IDを維持する。
3. **引当と一部出庫**：上記発注の④で当該発注の利用可能分を引当→一部を出庫（担当者入力）→共通在庫/引当残と出庫履歴の元明細を確認。履歴から元発注へ戻る。
4. **移管**：随時または移管管理から申請→確認→完了。杭の案件間移管は同一倉庫で割当先のみ更新、通信装置の倉庫間移管は場所別数量を更新。引当済ロットの倉庫移動でも元の発注明細を維持。完了済を再反映できない。
5. **前払・残金**：②で発注確定後、③の受領前でも⑤へ直接移動→条件から予定を生成→同じ操作を繰り返してもID・件数・金額を二重化しない。請求タブから⑤へ戻り、同じ予定へ請求を紐づける。

別途、直送のみの新規発注で④の「対象外」と倉庫在庫不変、入力区分/事業切替で下書きが混在しないこと、保存・再読込、容量不足時の復元/再試行、理由のない変更や受領数量未満への減数が拒否されることを確認する。
