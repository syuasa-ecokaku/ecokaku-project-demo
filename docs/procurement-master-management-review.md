# 購買の仕入先・担当者マスター

2026-11-12。既存の「設定 → マスター管理」に、共通と購買の分類を設けた。左メニューには各マスターを追加しない。従来の共通マスタ（電力会社・設備等）は「その他 → 既存の共通マスタ」で利用できる。

## 操作

- 購買 → 仕入先：仕入先コード、会社名、窓口担当者、メール、電話、有効状態、備考。コード・会社名は必須。コードは前後空白・全半角・英字の大小を正規化して重複を確認する。
- 共通 → 社員・担当者：社員コード、氏名、所属部署、有効状態、備考。コード・氏名は必須。同名でも社員コード・内部IDが異なれば別社員として登録する。
- 購買 → 担当者設定：共通社員を選択し、表示順（0以上の整数）と購買担当としての有効状態を設定。氏名・部署は社員マスターを参照する。同じ社員の重複割当は不可。登録後の対象社員は固定し、状態・順番を編集する。
- 購買担当者は、社員と担当者設定が両方有効なときだけ、新しい選択肢に表示する。表示順が同じ場合は社員コードで並べる。
- 購買①の「仕入先マスターを開く」「担当者設定を開く」から移動できる。「購買の入力へ戻る」で事業・タブ・入力区分・検索条件・未保存の購買編集を復元する。マスターを保存しても購買の未保存編集は保存しない。

## 初回引継ぎと履歴

既存のユーザー管理はアカウント・権限の操作例で、社員コードや社員IDを持つ社員マスターはなかった。共通社員マスターを設け、既存ユーザーの架空氏名・部署を初期情報に引き継ぐ。既存の購買デモ担当者2名も初期登録し、購買担当者に割り当てる。アカウント権限との自動同期・認証は追加しない。

仕入先は `supplier-a/b/c` の内部IDと既存の支払条件初期値を維持する。新規仕入先の支払条件初期値は個別確認で、発注の②で設定する。

発注には次を保持する。

- `supplier`：安定した仕入先ID。
- `supplierNameAtOrder`：発注時の仕入先名称。旧データでは取得可能な旧名称を初回だけ記録する。
- `ownerEmployeeId`：共通社員ID。
- `owner`：発注時の担当者名（旧文字列の互換と履歴を維持）。
- `ownerDepartmentAtOrder`：発注時の所属部署。

名称文字列の旧担当者は、社員マスターで名称が一意に一致した場合のみ対応付ける。候補なし・複数一致は `ownerEmployeeId` を空に保ち、元の文字列を「旧データ・未対応付け」として表示する。後から社員を追加しても既存の未対応付けを勝手に統合しない。正しい社員を購買で選択して対応付けられる。

下書きの選択時と発注確定時に名称を記録する。確定済み発注の名称を、マスター改名で書き換えない。過去の表示には発注時名称を使用し、現在名が違う場合は併記する。無効な設定済み値は「無効」を付けて残し、その選択肢は変更先として選べない。過去発注の他項目の更新を妨げない。

検索条件では過去に使用した無効な項目も選択可能。仕入先・担当者とも内部IDで検索するため、改名後も同じ対象を検索できる。旧名称・現在名もキーワード検索で参照できる。未対応付けの旧担当者は専用の旧名称条件で検索する。

## 保存

既存の `lifecycleTransaction` と親画面の保存ブリッジを使用し、同じローカル保存データに `masterData` を追加する。`suppliers`、`employees`、`purchasingAssignees` は共通の管理単位。購買の台帳とは別に保持し、レビュー用の購買初期化でもマスターは初期化しない。

初回データはマスター未保存の場合のみ作成。保存後は既存配列・有効状態をそのまま復元する。コード・IDを使い回した再登録や再読込による重複作成、無効状態の再有効化を行わない。保存失敗時はマスター・購買実績を巻き戻し、マスター入力と購買下書きを残す。再保存可能。

同一ブラウザー・同一URL内の保存。サーバー共有・端末間同期・実際のユーザー権限管理は対象外。マスターに削除操作は設けず、有効・無効で運用する。
