# 法務・蓄電池の仲介列と権利譲渡契約

作業ブランチ: `feat/legal-battery-broker-rights-transfer`。開始コミット `152a528`。先行の電力申請・不動産開発改修および既存の未追跡 `.agents/` は保持。適用対象のAGENTS.mdなし。mainへのマージ・本番公開は行わない。

## 実装

対象は法務 → 蓄電池。入力区分は既存の「契約対応」「設備販売契約（契約単位）」「土地売買契約（非課税のデモ）」「保守契約（契約単位）」を維持し、末尾に「権利譲渡契約」を追加。

既存コードに権利譲渡契約の入力項目はなかったため、入力欄を独自に作らず「権利譲渡契約の入力項目は未設定です。項目確定後に追加します。」と表示する。案件番号・案件名・詳細への操作と、他の区分の下書きに対する保存・取消は引き続き利用できる。契約種別・契約レコードは勝手に追加しない。

「契約対応」の列は、案件番号 → 案件名（共通参照）→ 担当者 → 仲介 → 進捗ステータス → 対応期限 → 次の対応 → 詳細。既存契約区分の業務列は変更しない。

仲介はテキスト入力で、既存の共通編集・下書き・入力チェック・保存・取消・変更履歴の処理を使用する。Tab／Shift+Tab、黄色の未保存表示、非表示案件・区分を含むまとめて保存と取消を維持する。既存の進捗ステータスは契約状態から計算する読み取り専用欄のまま。

共通の業務情報を使用するため、案件詳細でも同じ保存値・下書きを参照できる。太陽光・データセンターの法務画面には追加しない。

## 仲介の保存先

同一蓄電池案件には電力申請の保存済み仲介者 `case.power.values.brokers` が存在する。これを法務の `broker` 編集キーから参照・更新し、法務専用の重複した仲介レコードは作らない。顧客名・担当者名・地権者名から補完しない。

既存値は文字列または複数名の配列として扱う。法務ではテキスト欄に複数名を「、」区切りで表示・入力する（プレースホルダーでも案内）。名称自体の「、」は `\、`、バックスラッシュは `\\` で表現し、元の名前へ戻せるようにする。保存時は空白・空項目・重複を除いて同じ共有配列へ書き戻し、空欄なら空の配列となる。

未編集の仲介値は、他項目の保存で書き直さない。保存済みの仲介だけが電力申請サマリーの仲介候補・検索へ反映され、未保存の法務下書きは含まれない。別画面で保存値が変わった場合は既存の競合チェックで保存を止め、下書きを保持する。

初期10案件には仲介が未登録のため、初期欄は空白。架空の仲介名をデモ初期データへ追加しない。検証用の名称はブラウザ検証時のみ入力・注入する。
