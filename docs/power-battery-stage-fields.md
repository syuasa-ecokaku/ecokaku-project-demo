# 蓄電池の電力申請：確定した工程・入力項目

## 対象と画面

電力申請 → 蓄電池 → データ入力を変更しています。サマリー／データ入力／案件詳細、既存の検索・担当者選択・保存／取消を維持します。太陽光・データセンター、他部門の入力方法は変更していません。

| 順 | 工程選択 | 入力項目・変更 |
| --- | --- | --- |
| 1 | 基本情報・設備 | 既存の起案・基本設備情報と設備明細編集をそのまま再利用。別の保存先は作成しない。 |
| 2 | 事前相談 | 担当者、事前相談申請日、回答日。共通状態・共通期限・本申込等は表示しない。 |
| 3 | 接続検討 | 共通期限、接続検討料の支払期限、回答文書の受領日、本申込後の工期を一覧から外す。No.34の列名を「所要工期（月）」へ変更。 |
| 4 | 本申込・支払 | 既存のまま。 |
| 5 | 名義・設備変更 | 既存のまま。 |
| 6 | 連系準備・受電 | 既存のまま。 |
| 7 | 商用運転・市場参入 | 既存のまま。 |
| 8 | 取下 | 担当者、取下日、取下理由（複数行）。共通状態・共通期限は表示しない。 |

各一覧には案件番号・申請案件名の固定列と「詳細」を残します。事前相談・取下は、共通の案件識別2列＋指定の業務3項目＋詳細の6列です。取下理由は複数行のテキスト欄で、Enterは改行、Tab／Shift＋Tabは前後の編集欄へ移動します。列削除による空列は追加していません。

## 1～11の対応

1. 基本情報・設備：既存の先頭区分を維持し、二重追加しない。
2. 事前相談：基本情報・設備の直後に追加。最終順序は上表の8区分。
3. 事前相談：担当者＋専用の日付2つだけを表示。
4. 接続検討：対応期限（共通）の列を非表示。
5. 接続検討：接続検討料 支払期限日の列を非表示。
6. 接続検討：接続検討回答 文書受領日の列を非表示。
7. 所要工期（月）：データ入力・接続検討での列名、入力欄の説明・エラー表示を変更。保存キー`34`、整数入力、月単位、既存値、連系見込計算は維持。対象外の詳細・履歴では既存の項目名を保持。
8. 接続検討：本申込後の工期（月）の列を非表示。
9. 取下：担当者＋専用日付＋専用の複数行理由に整理。
10. 取下：対応状態（共通）は表示せず、取下日を表示。
11. 取下：対応期限（共通）は表示せず、取下理由を表示。9～11で同じ欄を重複追加しない。

## 保存先・申請回

新設項目は既存の案件の`power.values`と、`powerDrafts[案件内部ID]['v:項目キー']`を使います。基本設備情報は従来どおり`power.intake`を使い、ここへ日付・理由を複製しません。

| 項目 | 専用保存キー |
| --- | --- |
| 事前相談申請日 | `preconsultationAppliedAt` |
| 回答日 | `preconsultationAnsweredAt` |
| 取下日 | `withdrawalDate` |
| 取下理由 | `withdrawalReason` |
| 担当者 | 既存の`owner`を共用。新しい担当者マスターなし。 |

旧案件の新設項目は空欄です。共通状態・期限から日付や理由を推測して補完しません。非表示にした`commonDue`、`connectionDue`、`connectionReceived`、`35`は保存データ・詳細・履歴・計算から削除しません。No.35を利用する計算も従来どおりです。

一括保存は、既存どおり絞り込みや区分切替で非表示の下書きも対象です。未保存の黄色表示、変更件数、日付の検証、取消、保存失敗時の巻戻し・下書き保持、ブラウザー内の保存と再読み込み復元を共用します。保存は同じブラウザー・URL内であり、サーバー共有ではありません。保存前の下書きは再読み込みでは復元しません。

再接続検討で新しい申請回を開始する際は、4つの新設項目も旧申請回の`archives[].values`へ退避し、新回の入力は空欄にします。案件内部ID、他案件の値、共通担当者・状態・期限は維持します。既存の再接続検討の確認・保存トランザクションを利用します。

## 案件詳細・取下の意味

案件詳細の「基本情報・設備仕様」に事前相談の保存済み値、「履歴・タスク・関連書類」に取下の保存済み値を表示します。申請回を併記し、取下理由の改行も表示します。入力中の下書きを保存済みとして見せず、編集はデータ入力の該当区分で行います。旧申請回の値は従来の退避履歴から参照できます。

取下日・理由を保存しても、案件全体の状態・進捗判定は変更しません。取下実行ボタン、新しい承認フロー、事前相談による自動的な工程変更は追加していません。サマリーの現在工程とデータ入力の現在工程フィルターは従来の判定を使用します。

## 動作確認

`python tests/power_battery_stage_fields_smoke.py`で、旧保存データの無変更引継ぎ、8区分と列、既存基本情報の共用、専用日付と複数行理由、Tab、保存・取消・絞り込み、他案件との分離、保存失敗・再保存・再読み込み、申請回の退避、所要工期・全連系見込計算の維持を確認します。

また、対象外の蓄電池5区分の一覧表と、61の対象外画面を前リリースと比較します。結果・画面は`/tmp/ecokaku-power-battery-stage-fields/`です。既存の電力申請・連続入力・工程フィルター・起案／採番／承認・購買のブラウザーテストも回帰確認します。

デモのサンプルデータは追加・初期化していません。検証中の入力はテスト専用ブラウザー内の架空データです。
