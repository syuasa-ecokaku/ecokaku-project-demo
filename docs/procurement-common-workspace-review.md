# 購買の共通3タブ・一覧入力

担当者向けの操作手順は [ブラウザー版](purchasing-manual.html) ／ [PDF（10ページ）](purchasing-manual.pdf) を参照。業務フローは2ページ、基本操作は3ページ、データ構成図は9ページ。

2026-11-11。公開済み `4b224aa` を基に、購買だけを「サマリー／データ入力／案件詳細」に統一した。以前の5タブ維持の指定は今回の指示で撤回されたため、上位に購買固有タブを残さない。適用対象のAGENTS.mdは見つからなかった。既存の在庫計算・ID・保存方式・支払条件を維持し、経理・会計連携・全社キャッシュフローは変更していない。

## 旧画面からの移動先

| 旧5タブ | 現在の入口 |
| --- | --- |
| サマリー | サマリー。共通のKPI、状態別件数、直近の予定・期限、対応が必要な対象。KPIから入力区分・絞り込みへ移動 |
| 発注管理 | データ入力①購入準備・②発注/納期・③荷受、および案件詳細の関連発注。案件未指定も発注詳細で参照可能 |
| 入出庫・在庫 | データ入力④。在庫全体はサマリーの「在庫一覧を見る」からも確認 |
| 移管管理 | データ入力⑥。移管明細・変更履歴・数量反映の入口を統合 |
| 請求・支払予定 | データ入力⑤。案件詳細にも同じ対象発注の請求と複数予定を参照表示 |

既存の `du-work-tabs`、`du-filters`、`du-savebar`、`du-bulk-table`、`du-dirty`、`du-invalid`、事業切替、`departmentKpiDesign`、`StatusCountCard`、`UpcomingScheduleCard` を利用。他部門の一案件一行モデルに合わせてデータを潰さず、購買固有の管理単位ごとに行を分ける。

## 日常の操作

1. 事業を選択し、「データ入力」へ。
2. 案件・発注番号・仕入先・担当者・製品・状態・期間を絞り込み、①〜⑥の入力区分を選択。
3. 一覧のセルを編集。黄色が未保存、赤色が入力エラー。Tab／Shift＋Tabで連続入力。
4. 「変更をまとめて保存」で、選択事業の非表示行・全入力区分を保存。「未保存の変更を取り消す」で、その事業だけの編集を取り消す。
5. 複数明細・受領・引当・出庫・請求・移管などの補助画面は「親画面の未保存へ追加」で一覧に戻す。この時点では保存・数量反映をしない。親の保存・取消と同じルール。

区分・タブ・事業を変えても未保存の編集は保持する。他事業の未保存変更を、現在事業の保存へ含めない。保存前の再読込では未保存の編集は復元しない。保存済みの台帳と業務操作の準備行は同じブラウザー・同じURLで復元する。ファイルは名前のみ保存し、本体は保存・送信しない。

### 入力区分と一行の単位

| 区分 | 表示・編集する行 |
| --- | --- |
| ① 購入内容・発注準備 | 発注行：購入区分・仕入先・担当者・備考。明細行：使用案件・製品/型番・数量/単位・在庫/費用・備考 |
| ② 発注・納期確認 | 発注行：番号・日付・支払条件・変更理由。明細行：単価・税・金額・納期・直送/倉庫・場所・予定荷受人・配送。①の製品・数量は参照 |
| ③ 納品・荷受確認 | 発注明細ごとの累計/未納、納品実績一件ごとの履歴、未実行の受領準備一件ごとの入力行 |
| ④ 在庫・引当・出庫 | 製品/型番/場所の共通在庫、使用予定一件、確定引当残一件、出庫実績一件。引当と出庫の準備行も別表示 |
| ⑤ 請求確認・支払予定 | 発注全体の照合、仕入請求一件、支払予定一件。請求・発注・予定の意味と差額を分ける |
| ⑥ 移管・変更 | 移管記録一件、完了準備一件、発注明細の変更/取消への入口、理由付き変更履歴一件 |

各表に「1行＝…」を表示。発注・明細を固定列として参照できる。実績の数量・日付・関連付けは直接編集しない。購入前の下書きと、発注を確定する操作も分離する。

### 数量に影響する業務操作

受領・引当・出庫・引当解除・移管完了の補助画面は、入力内容を**業務操作の準備**として扱う。

- まず親画面で「変更をまとめて保存」。準備が保存されても実在庫・引当・未納残は変わらず、在庫の確保もしない。
- 一覧の「入庫・受領を登録」「引当を確定」「出庫を登録」「移管を完了」などを押す。
- 増減する数量を確認し、実行。現在の受領残・在庫・引当・移管状態を再検証して一度だけ反映。
- 実行後は準備行をなくし、同じIDを実績IDとして記録。移管完了では対象移管のIDを維持する。二重登録・二重反映をしない。
- 選択事業に未保存の入力があれば、先に保存または取消する。数量・場所の状況が変わって実行できない場合は、保存済み準備を保持して理由を表示する。

準備行の追加は `workItems`。実績は既存の `receipts/allocations/issues/transfers` のまま。元入庫の `sources` を引き継ぎ、在庫は既存の実績から計算する。移管は全社在庫を増やさず、支払予定を作らない。直送・送料/保管費の実績は倉庫在庫を増やさない。

## 案件フィルターと案件詳細

案件フィルターは「すべて」が初期値。「案件未指定」は空の案件IDだけ、各案件はその案件IDだけを判定する。

- 発注行：該当明細がある発注を表示。「該当明細数／全明細数」を示し、発注全体で共通する仕入先・条件などを編集する。
- 明細・受領行：フィルターに一致する明細だけを表示。混在発注の他案件明細は一覧へ混ぜない。
- 引当・出庫・使用予定：対象案件で判定。実在庫自体は案件属性を持たない製品・場所単位の共通残なので、案件別按分として表示しない。
- 移管：元または先案件が一致する記録を表示。「案件未指定」は元/先の双方が未指定の記録だけ。期間は申請日、発注状態は下の発注変更一覧に適用。
- 請求・支払予定：該当発注の全体の記録であり、案件別按分は未対応。その範囲を表と照合欄に明記する。

案件詳細は共通の案件情報を参照し、直接案件へ紐づく明細に加え、元入庫から辿れる引当・出庫の発注も表示。複数発注を保持する。案件の移管履歴は案件単位で一度だけ表示する。

「データ入力で編集」は案件ID・発注ID・入力区分を引き継ぐ。サマリーの対象行からは、検索・案件・製品などの絞り込みを維持して対象発注を追加する。事業全体を示すKPI・予定からは、その対象に合わせて絞り込む。案件未指定の発注を案件詳細へ載せるための架空P番号は生成しない。未指定分はデータ入力または発注詳細で参照する。

## データ引継ぎ・保存範囲

既存の親ページを介した保存キー、schema、案件カタログ、発注・明細・実績・請求・予定のIDは変更しない。画面変更を理由に自動初期化しない。`workItems` がない保存データには空配列を補うだけ。

旧版で保存された `inputDrafts` は、事業ごとの新しい未保存バッファへ読み込む。台帳へ自動反映しない。現在事業で明示的に保存または取消した時だけ、その事業の旧下書きを片付ける。他事業の旧保存下書きは残り、再読込後も引き継がれる。

新しい編集中バッファは事業・管理単位・内部IDごとに保持し、保存対象以外の事業の入力をsnapshotへ混ぜない。保存は既存の更新シーケンス・排他処理・容量エラーの復元を利用。エラー時は対象事業の入力を保持し、全体を中途半端に反映しない。

## 変更・仮設定・制約

- 新規発注の購入区分の初期値は在庫向け。案件向けへ変更でき、確定時には明細ごとの案件を検証する。未入力の発注・明細は下書きとして保存可能。
- 確定済の発注内容・価格・数量・納期などの変更は理由を入力する。納品/取消実績がある明細の製品・案件・単位・区分・方法・場所を固定し、数量は受領済＋取消済未満にできない。
- 未納取消は補助画面で理由を入力し、親の保存で未納残だけを取消。納品実績は保持し、支払予定の精算は自動実行しない。
- 未完了移管は数量・移管元/先・場所などを編集できる。主要項目の変更理由を必須とし、変更前後を移管の履歴へ記録。完了済の数量・紐づけは固定する。
- FIFOによる元入庫の選択・旧実績の追跡情報の推定、担当者1段階の移管確認は引き続き仮設定。
- 数量と単価は整数、税は明細ごとの切捨て。50/50・30/70・翌月末100％の代表条件、最終納品予定日・暦日による計算を維持。営業日・休日補正・外貨は未対応。
- 返品、実績の数量訂正/削除、使用不可品の復旧/廃棄、価格変更後の請求書自動訂正、前払精算、会計連携、経理の支払確定/実績は未対応。
- レビュー用初期化は「補足・確認用メニュー」へ移動。全事業の購買の保存済み台帳・未保存編集が失われる旨を明示し、確認後に実行。他部門は保持。
