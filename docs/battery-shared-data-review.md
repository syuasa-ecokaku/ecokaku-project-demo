## 事業別の分離と共通データ

ユーザー確認により、既存の蓄電池10番号を維持し、太陽光にも存在する `P-00001` / `P-00002` / `G-00003` は **事業ID＋案件番号**でデータを区別した。太陽光の既存名称・顧客・契約・金額・日付は変更しない。同一番号から事業を推測しない。

- `batteryCaseSeedData` / `batteryCases` / `batteryCaseMap`：蓄電池の共通案件。案件番号、名称、所在地、顧客、正式化確認記録、契約・設備・部門業務を保持。
- `batteryDepartmentDefinitions`：部門ごとの列、型、ステータス、予定、KPI設定。正式な業務仕様とは断定しない。
- `batteryStore`：案件ごとの値は共通案件にある当該部門の値を参照。7つの別案件マスタは作らない。下書き・添付名・対応／変更履歴は部門・事業・案件で分離。
- `batteryBinding`：設備販売契約を営業／法務、土地契約を不動産／法務で共通参照・更新。営業の完工／検査／引渡し予定は工事の共通予定を参照。ANDPAD IDは電力申請から工事へ参照し、実連携は行わない。
- 共通案件名・所在地は参照表示。電力申請の申請案件名・申請住所は申請時点の独立値を保持する。
- 保存前に日付・数値・共有値の競合を検証。エラー時は他の下書きも保持。非表示案件・入力区分も保存／取消の対象。蓄電池の保存対象は他事業と分離し、画面にも明記。
- 法務は案件単位の行を維持しながら、設備販売／土地売買／保守契約の区分で列を切替。契約ID・番号・確認・承認・締結・金額は契約レコード単位。未締結には締結日を設定しない。
