# メンテナンスの自社開発引継ぎ・単独受託

## 受託データ

既存の共通案件カタログ、固定内部ID、部門の入力・下書き・保存／取消、契約配列、設備配列、点検／障害記録配列、変更登録を拡張する。別のP/M対応表や重複案件は作らない。

- `source.maintenance`：`route`（internal / standalone）、受託区分の日本語名、受入状態、案件状態、顧客・契約先、設備所有者、開始予定／実績、受入担当・実行者・日時・引継ぎ事項・イベント履歴。
- P案件：同じオブジェクト・内部ID・P番号を維持。既存部門との紐付けも維持する。
- M案件：既存のUUID案件生成と共通採番関数で `M-00001` を発行。メンテナンス単独のカタログ領域から共通案件カタログへ登録する。開発各部門のレコードや電力申請の対象配列へ追加しない。正式化承認レコードも作らない。
- 契約：既存の `source.contracts` 内の保守契約を使用。契約IDと `caseId: source.internalId` で紐付ける。旧レコードのIDは変更しない。設備・点検・対応記録にも内部案件IDを保持する。

P/Mの表示文字から所有者や運用状態を決めない。受託区分、受入状態、案件状態を使用する。顧客・契約先と設備所有者は別項目。所在地の一致だけでは別設備の起案を禁止せず、共通の既存案件候補確認を利用する。

## 自社開発からの受入条件

既存の正式化承認済みP案件で、工事の `handoverActual`（引渡し実績日）と電力申請のNo.89（受電・送電実績日）が保存済みであること。日付の有効性・未来実績でないことを再確認する。予定日から実績を推定しない。受入時も再判定し、管理開始日は両実績以降・当日以前とする。

既存の実績項目に「カットオーバー」という独立項目はないため、この組み合わせをモックの判定として明示した。太陽光・データセンターの開発側では実績項目が未整備のケースがあり、その場合は条件未登録として引継ぎを止める。事業ごとの正式なカットオーバー定義は要確認。

既に保守中だったP-00001は実績と既存の保守状況を確認して移行する。元の受入日時・管理開始日・実行者は未記録と表示し、現在日時を過去の受入履歴として補完しない。旧データ移行済みの印を保持し、その後の通常保存や再読み込みだけで新たな受入を成立させない。他の引継ぎ前の開発案件のデータも削除せず、従来の準備情報は詳細から参照・編集可能にする。受託情報の編集は受入確定後に限る。

## 契約・履歴

契約名、契約番号、契約先、締結確認状態・締結日、開始／終了、自動更新、申出期限、業務範囲、金額・請求周期、ファイル名、備考を保持する。契約書の選択では締結状態を更新しない。

契約更新は新しい内部契約IDを追加し、`previousContractId` で旧契約を参照する。旧契約を上書きせず、案件番号・枝番は増やさない。一覧の契約は選択済みの有効契約を優先し、終了した契約を現在契約として表示しない。更新契約が将来開始の場合、開始前は現在有効な旧契約を表示する。全契約終了時は「終了／現在の有効契約なし」とする。契約満了日・申出期限の30日以内を表示・絞り込み可能。自動更新設定は記録のみで、期間の自動延長は行わず、新しい契約レコードで更新を確認する。

点検・緊急対応は共通の `records.inspections / incidents` に追加する。予定と実績、担当者、内容、対応結果、資料名を分ける。既存の代表設備の入力欄と記録も維持し、同じ配列へ接続する。契約更新後も消去しない。

## 検索・集計

メンテナンスの事業別受託一覧は受入済みPと単独M。受託区分、案件状態、契約状態、担当者、従来の進捗・期限・キーワードをAND条件で絞り込む。案件検索は現在／旧番号・枝番、名称、所在地、顧客・契約先を対象とする。一つのリセットで追加条件も解除する。

KPI・状態グラフ・予定カードは事業と検索・受託区分等の条件に連動する。KPI自身の選択条件を除いてKPIを集計し、一覧はKPI条件も適用する。管理中と商談中を区別し、管理設備数は管理中案件の設備だけを数える。全社でもM案件の商談中／契約手続中は稼働中件数に入れず、案件カタログの総数には一件として保持する。P受入、契約更新、記録追加では案件総数を増やさない。

## 保存と制約

前回の親画面経由のブラウザー内スナップショット保存を利用する。新しい保存基盤は追加しない。登録・採番・受入・契約・履歴を一つのトランザクションで扱い、保存失敗時は追加フィールドも含めて元へ戻す。旧データに受託項目がなくても開ける。

明示的な共通「変更登録」だけがM-00001-01等を発行する。通常保存・受入・契約更新・点検履歴追加は枝番を進めない。

保存は同じブラウザー・オリジン・パス内。ファイル本体、サーバー共有、本番の認証・認可、実監視、複数端末の採番保証は未実装。Web Locks非対応の同時保存制約も共通保存と同じ。画面へ入力する情報は全てダミーのみ。
