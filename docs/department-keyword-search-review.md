# 6部門共通のキーワード検索

作業ブランチ: `feat/department-keyword-search`。開始コミット: `be7b828`。追跡ファイルの未コミット変更なし。既存の未追跡 `.agents/` を保持。適用対象のAGENTS.mdなし。mainへのマージ・本番公開は行わない。

## 実装範囲

不動産開発・営業・法務・購買・工事・メンテナンスの、蓄電池／太陽光／データセンターへ適用。既存の案件検索エリアがある39画面（6部門×3事業×サマリー・データ入力の36画面、不動産開発の3事業の案件詳細3画面）が対象。それ以外の案件詳細へ新しい検索エリアは追加していない。

各検索欄は「並べ替え → キーワードで検索 → 絞り込みを解除」の順。共通の検索欄描画と検索・状態更新処理を使用する。既存の汎用部門画面と、太陽光／データセンター営業の旧画面はデータへのアクセスを分け、検索方式・入力動作・解除は共通にした。

従来この6部門には一般条件をまとめて解除するボタンがなかったため、同じ検索行へ追加。既存の「KPIの絞り込みを解除」は保持。新しい全条件解除では案件検索・キーワード・担当者・状態・期限・KPI条件をクリアし、並べ替えを初期の案件番号順へ戻す。下書き・保存値は変更しない。

## 検索方式と状態

電力申請の既存関数 `powerSummaryText` をそのまま再利用し、前後空白除去・英字大小を区別しない部分一致に統一。空欄・空白だけはキーワード条件なし。既存の案件番号／案件名検索とは別の入力欄で、担当者・ステータス・期限・KPI条件とANDで組み合わせ、最後に既存の並べ替えを適用。

入力するだけで一覧・表示件数を更新する。フォーカス・カーソル・選択範囲を復元し、IME変換中は再描画せず確定後に反映する。条件は部門・事業ごとに保持し、同じ部門・事業のタブ間で共有。タブ・入力区分・事業・部門を切り替えても下書きを消さない。

一覧の表示件数は絞り込みに連動。KPI・工程件数・予定は、この6部門の既存仕様である事業全体集計を維持する。電力申請のKPIが検索条件内で集計される既存仕様も変更しない。

PCでは入力欄の最小幅220pxを基本に自然に折り返す。入力欄の高さは既存と同じ34px。スマホでは1列・利用可能な領域の全幅とし、既存の左メニュー・文字サイズを維持。新規CSSは対象6部門の検索行だけに限定し、電力申請・KPI・お知らせ・承認管理のデザインは変えない。

## 実際の検索対象

共通: 保存済みの担当者・進捗ステータス・次の対応・期限超過の注意表示。蓄電池の仲介者・仲介会社名は、同じ共通案件の `power.values.brokers` を参照する。入力中の法務の仲介下書きは含めない。事業をまたいで同じ表示番号の案件を結合しない。

| 部門 | 部門固有の保存済み検索対象 |
| --- | --- |
| 不動産開発 | 地番、地権者／権利者、土地契約書番号、関連契約番号 |
| 営業・蓄電池 | 顧客名、設備販売契約書番号、契約確認状況、承認状況、締結状況 |
| 営業・太陽光／データセンター | 既存営業モデルの顧客名、営業ステータス、次の対応、販売契約書番号。未登録事業に案件は追加しない |
| 法務・蓄電池 | 設備販売・土地売買・保守の各契約書番号、契約確認状況、承認状況、締結状況 |
| 法務・太陽光／データセンター | 既存モデルの販売／土地契約書番号、契約の登録状況。未設定の担当者等は補完しない |
| 購買 | 発注番号、仕入先／発注先、支払状況（該当する既存項目がある事業のみ） |
| 工事 | 共通の担当者・進捗・次の対応・仲介情報・期限超過表示。工事備考などの未定義項目は新設しない |
| メンテナンス | 点検記録、障害対応記録、対応区分 |

項目定義が存在するものだけを参照する。汎用の「備考」欄は現行コードにないため追加せず、各部門の既存の「次の対応」、メンテナンスの「点検記録」「障害対応記録」等の自由記述を検索する。電力申請の状況メモは他部門固有の備考として流用しない。

案件オブジェクト全体の文字列化はしない。内部ID、案件番号・案件名、ANDPAD ID、住所、添付名、操作履歴、承認履歴、数値・日付欄、未保存の下書きはキーワード対象外。案件番号・案件名は従来の専用検索を使用する。検索可能な「契約書番号」「発注番号」は画面の業務項目であり、内部の契約ID／記録IDとは別。

プレースホルダーも部門・事業の既存項目に合わせる。仲介者項目のない他事業に仲介者検索の案内は出さない。条件に一致する案件がない場合は0件と表示し、既存データがあるサマリーでは専用の空状態メッセージを表示する。
