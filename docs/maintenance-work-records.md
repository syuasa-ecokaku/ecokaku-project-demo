# 点検・緊急対応記録の実績登録と完了操作

## 対象と操作

既存iframe内のP/M共通メンテナンス機能を拡張する。案件詳細の「設備・点検・緊急対応履歴」に、記録ごとの「内容を編集」「実施開始／対応開始」「実績登録・完了」「中止登録」「完了記録の訂正」「操作履歴」を配置する。新規追加は予定登録／実績登録を選択できる。予定・未対応から直接完了も可能。

既存の内部案件ID、設備ID、`source.records.inspections/incidents` の記録IDを使う。更新で別記録を追加しない。契約・設備・案件数・案件番号・枝番は変更しない。①の保守契約機能を維持し、全社の案件分類・稼働判定・案件全体の終了条件は変更しない。

## 状態と検証

- 基本点検：予定／実施中／完了／中止。
- 緊急・不具合対応：未対応／対応中／完了／中止。
- 開始は担当者必須。開始日時・実行者を保存する。
- 完了は実在する当日以前の実績日・担当者・結果が必須。予定日前の実施を許可する。直接完了時は開始日時を作らない。
- 中止は理由必須。元の予定・内容を保持し、削除しない。
- 完了訂正は専用操作と理由が必須。訂正後も完了に必要な情報を検証する。
- 設備は所属案件のものだけを選択可能。未指定も許可し、「対象設備未指定」と表示する。
- 関連資料は既存のファイル名を保持して追加する。ファイル本体は保存しない。

## 共通参照・集計

個別記録を正本とする。次回点検は未完了・未中止の点検にある明示的な予定日の最小値で、過去日も期限超過として残す。対象がなければ「未登録」。代表設備の点検・障害入力欄は参照表示と明示的な記録選択・編集への入口に変更し、任意の記録を上書きしたり重複する作業を自動生成したりしない。

障害対応中は未対応／対応中の不具合記録がある案件数、緊急対応はそのうち緊急優先度の記録がある案件数。複数記録でも案件を一度だけ数え、ほかの未完了記録が残る限り対応中を維持する。自由記述に過去の障害が残るだけでは対応中にしない。

一覧・KPI・直近予定・点検対応状態の絞り込みを同じ記録から算出する。未完了／状態未確認の「記録数」と、対応中等の「案件数」を区別する。全社カレンダーは従来の点検予定参照だけを整合させ、完了・中止した予定を除く。全社分類や契約終了による案件全体の判定は変更しない。

## 既存情報

明示的な状態がない記録は「状態未確認」。日付・メモ・結果の有無から予定・未対応・完了を推定せず、通常の未完了・緊急・予定集計に混在させない。確認専用操作から根拠と状態を登録する。従来の代表欄・記録の原文は保存し、詳細で確認可能。参照対象の自動対応は旧内容と一意に一致する場合に限定し、不明・複数候補では利用者が選択する。旧代表欄だけの予定を無条件に作業記録へ変換しない。

## 保存・履歴

親画面経由の既存 `lifecycleTransaction` とブラウザー内保存を使用し、別保存キー・別台帳を追加しない。記録とその `operationHistory` に内部案件ID・設備ID・記録ID・操作・日時・利用者・状態と内容の変更前後・理由を一体保存する。履歴は参照専用。

検証・キャンセルでは変更せず、保存中ロックと完了済みフラグで連打を防ぐ。保存エラー時は状態・履歴を一緒に戻し、フォームを保持して再試行できる。フォーム表示後に記録が変化した場合も保存を拒否する。再読み込み後は既存の復元処理で状態・履歴を復元する。

同じブラウザー内のデモ保存であり、サーバー共有・実認証・他端末同期は実装しない。関連資料はファイル名のみ。

## 検証結果

Chromium／Playwrightで以下を実行し、計38検証グループが成功した。

- `tests/maintenance_work_records_smoke.py`：11グループ。P/M同一ID、開始・直接完了・中止・訂正、必須／未来日、履歴、複数障害、最早予定／期限超過、旧状態確認、代表欄、設備所属、取消・連打・保存失敗・再読込、スマートフォン表示、番号・枝番・契約・分類の不変。
- `tests/maintenance_contract_operations_smoke.py`：9グループ。①の編集・締結・終了・更新と状態・保存を回帰確認。
- `tests/maintenance_intake_smoke.py`：10グループ。P引継ぎ・M登録・共通契約／記録・復元を回帰確認。
- `tests/department_notices_smoke.py`：8グループ。21サマリー、通知生成・重複防止・閲覧範囲・遷移、全社の業務／KPI／分類を回帰確認。意図的な点検カレンダー参照の変更は旧画面の完全一致比較から除き、専用テストで整合を確認。

JavaScriptエラー・ファイルアップロード・外部書込みは検出されなかった。ブラウザー容量不足を模擬してロールバックと再試行を確認した。実サーバー障害・複数端末の同時更新は対象外。
