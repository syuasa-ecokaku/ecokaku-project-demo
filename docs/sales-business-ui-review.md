# 営業部門：事業別・3業務タブへの統一

## 対象と保存範囲

- 作業ブランチ：`feat/sales-business-work-tabs`。
- `index.html` の iframe `data-srcdoc` 内にある実表示コードを変更。
- 営業の初期表示：蓄電池／サマリー。「全事業」は設置しない。
- データ・下書き・請求指示はブラウザー画面内のみ。再読み込みで初期化。サーバー保存・送信は行わない。
- 今回は実装とローカルブラウザー確認。本番への反映は行っていない。

## データの引継ぎ

ユーザー確認により既存3案件を太陽光に分類。案件番号や元データは変更せず、明示的な `salesMembership` に事業所属を保持。配列を使い、案件番号から事業を推測しない。蓄電池・データセンターは営業案件未登録。電力申請の蓄電池10件は営業へ複製していない。

`projects` は既存どおり法務と同じオブジェクトを参照。契約・請求指示・入金参照・完工／検収／引渡しを案件詳細に保持。既存の請求・入金・引渡しダッシュボードはサマリーの開閉欄に保持。

## UIと操作

- 事業タブ：蓄電池／太陽光／データセンター。既存Lucideの battery / solar-panel / server SVGを利用。業務タブ：サマリー／データ入力／案件詳細。
- 事業を切り替えても選択中の業務タブを維持。検索・ステータス・並べ替えを事業ごとに保持。案件名から詳細へ遷移し、一覧へ戻れる。
- データ入力は1案件1行、行52px、入力欄34px、番号・名称固定、見出し固定、横スクロール。既存項目を基本情報／契約／完工・検収・引渡しの入力区分に分ける。
- Tab／Shift+Tabで編集セル間移動。未保存セルは黄色、検証エラーは赤色。金額は0以上の整数。
- 複数案件・非表示の下書きもまとめて保存／取消。エラー時は全下書きを保持。法務から同一項目が更新された場合は競合を表示し、保存を止める。

## KPIと不足情報

- 管理案件数と営業ステータス別件数は選択事業の保存済みデータから集計。
- 既存ステータスは「契約準備」「契約締結」「検収済み」。商談中／契約予定の定義がないため、対応するKPIは「—」。契約準備を契約予定と断定しない。
- 営業担当者・対応期限・商談予定・提案予定・契約予定日は元データに存在しないため未設定。担当者・期限の絞り込みは未設定として操作不可。遅延件数／今月の契約予定件数は「—」。
- 請求の支払期限を営業対応期限とみなさず、契約実績日を契約予定日とみなさない。
- デモ基準日は2026-11-04と明示。

## 拡張箇所

- `salesBusinessConfigs`：事業名・アイコン。
- `salesMembership`：案件と事業の関連。既存案件オブジェクトを複製しない。
- `salesFields` / `salesGroups`：入力項目・型・選択肢・入力区分。
- `salesSummaryHTML` / `salesFiltered`：KPI定義・検索条件。担当者・期限・予定日を正式に定義した後に対応。
- 電力申請の設定・状態・描画処理は共用せず、そのHTMLと業務JavaScriptは変更前と一致。
