# 電力申請：事業種別と業務タブの2階層化

## 変更範囲

`index.html` の iframe 内、電力申請モジュールを拡張した。既存の蓄電池ワークフローを再実装せず、事業別の表示振り分けで包む形を採用。

- 初期表示：全事業／サマリー。画面タイトルの下に事業タブ、その下に業務タブを配置し、保存範囲の案内はタブの後に表示。
- 事業切替：全事業・蓄電池・太陽光・データセンター。既存LucideのSVG付き横並びタブを使用。上段は淡い青背景・濃い青の文字／アイコン・3px下線、下段は文字のみの控えめな業務タブとして区別。狭い画面では上段を横スクロールする。
- 業務タブ：summary／bulk／detail（サマリー・一括入力・詳細管理）。事業変更時も選択タブを維持。
- フォントは電力申請の領域内だけに Meiryo／メイリオを指定。
- ヘッダー・左メニューのDOM、他部門の実装、共通ナビゲーション、外側iframeの実行コードは変更していない。

## 既存データの引継ぎ

今回の指示に従い、既存の電力申請サンプル3件を蓄電池ワークフローに引き継ぐ。旧サンプルには共通案件名に「太陽光」を含むもの、設備区分が「太陽光」のものがあるが、既存値・名称は変更しない。事業と設備区分は別に管理し、案件番号の接頭辞や設備区分から事業を推定しない。

`powerProjectBusinesses` に明示的な事業所属配列を持ち、同じ案件が複数事業に所属できる構造とした。今回の所属設定は3件とも `battery`。太陽光・データセンターの実案件として自動再分類したり、架空案件を追加したりしていない。

既存の工程番号と `powerSchemas` の内容は変更していない。接続検討・本申込・契約／負担金・連系・添付・履歴・タスク・再接続検討・月末計算・番号照合、保存／下書き処理は維持。

## 全事業

保存済みサンプルから全案件数・対応中・遅延・今月期限のKPIと、事業別進捗・案件一覧を生成。太陽光・データセンターは未登録として「—」を表示し、0件の実績や架空の件数を表示しない。サンプル集計であることを明記する。

KPIは案件番号で重複排除する。事業別集計と一覧は事業所属単位のため、将来複数事業に属する同一案件があってもKPI総案件数を二重計上しない。

共通項目として担当者・対応状態・対応期限を追加。サンプルの対応状態と期限を明示的に初期設定し、既存の工程状況・タスク期限を上書きしない。

- 対応中：共通対応状態が「対応中」。
- 遅延：未対応項目の登録期限超過、または完了以外の共通対応期限超過。
- 今月期限：共通対応期限または未対応項目の期限がデモ基準月に該当。
- 基準日：既存と同じ `2026-11-04`。対象外項目は判定から除外。

全事業の一括入力は共通3項目だけを編集できる。共通案件名は参照表示とし、他部門の共通データを変更しない。共通項目の保存・取消では、事業固有の入力・添付名・タスク等の下書きを保存・取消しない。隠れた事業固有項目の入力エラーで、共通項目の保存が阻害されることもない。

全事業の詳細管理は、各事業の個別詳細への入口とする。

## 準備中の事業

太陽光・データセンターは全3タブで指定の案内を表示する。入力欄・工程・添付・保存ボタンを設けず、蓄電池の項目をコピーしていない。

- 太陽光：「太陽光発電の業務項目は現在整理中です。確定後に実装します。」
- データセンター：「データセンターの電力申請業務項目は現在整理中です。確定後に実装します。」

## 今後の追加箇所

実際に表示されるソースは `iframe[data-srcdoc]` 内。編集時はその内容を復号して対象コードを修正し、HTML属性として再エスケープする。外側の画面に未使用コードを追加しない。

1. `powerBusinessConfigs.solar`／`.datacenter`（事業追加時のアイコン対応は `renderPower` の `businessIcons`）
   - 確定した固有項目を `fields`／`schemas`、工程・進捗を `stages`／`sections`／`sectionKeys`、一括入力列を `bulkStages`／`bulkKeys` に定義する。
   - 各タブの `render`、工程表示の `stageLabel`、未対応判定の `issues` を事業固有の実装として追加する。
   - 全事業からの共通項目編集を実装する場合は `commonEditor` と共通保存アダプター・詳細への遷移も追加する。現時点では蓄電池だけが実装済みで、準備中事業へ蓄電池の保存処理を流用しない。
   - 検証完了後に `ready` を有効にする。フラグだけを変更して未実装機能を動作可能と扱わない。
2. `powerBusinessStores`
   - 事業ごとに `records`・`drafts`・`badInputs` を分離している。蓄電池の既存 `powerData` 等は `battery` ストアの互換参照。
   - 工程No.24等は、事業の `fields` と事業別レコード内で保持する。別事業の同じ番号を同一キー空間へ混ぜない。
3. `powerProjectBusinesses`
   - 確認した案件所属を配列で設定する。G-/R-/P-の案件番号体系は変更せず、複数所属もここで扱う。
4. `powerRegisteredBusinesses`／`powerBusinessMetrics`／`powerSaveCommon`
   - 確定した各事業のデータ供給・共通項目保存アダプターを接続する。未登録データを架空値で補完しない。
