# 電力申請モック 追加ヒアリング反映

## 対象と根拠

- 対象：`index.html` の `iframe[data-srcdoc]` 内で実際に表示されるアプリケーション。
- ブランチ：`feat/power-application-hearing`。開始時点の main は `7ee50e93a1422056733ea435de34bd15882f5763`。
- ユーザーの今回の修正指示を根拠に実装。指定された Excel「1027_電力申請_103項目チェック_一次分析(1).xlsx」は添付・取得先が確認できず、L列との直接照合は未実施。
- Excelを取得できた場合はL列を最新回答として優先し、J列の原回答・K列の古い分析で上書きしない。今回、旧分析の一律「追加確認あり」表示と原回答の転載は除去した。
- 既存の未追跡 `.agents/` は保持し、この変更のコミットには含めない。

## 修正内容

既存の6タブと画面レイアウトを維持し、以下を実装。

1. **基本・設備**：共通参照と独立した申請名・住所、ANDPAD ID、近接配置した申請出力・定格容量、技術部管理サンプルマスタと連動するアグリゲーター・メーカー・単一型式選択、整数台数、複数行キュービクル。アグリゲーター変更履歴。
2. **接続検討・支払**：請求書受領・期限・経理参照支払日・証憑送付日を分離。22万円を表示。回答の文書発行日と受領日、受付日と番号を区別。回答予定日変更履歴。
3. **本申込・負担金**：送配電への本申込と小売への接続供給申込、発調本受付書面発行日と受付条件を明記。保証金10%と負担金差額は参考表示のみ。請求書記載額を自動上書きしない。アグリ名義の最新負担金は従前額と比較。
4. **連系見込**：採用段階を画面内で選び、接続検討の2予測日の遅い日／No.54／協議見込日を採用。起算日不足時は算出せず、月末・うるう年を考慮。負担金起算は予定／実績を明示した選択案。根拠と更新履歴を保持。
5. **関連手続き**：エコ革名義の要否確認と本回答後の設備変更確認を分離。地位移転の3日付、自由な申請主体、固定IP申込日、書面由来の地点番号2欄と照合、先頭ゼロ保持、系統コード補足、支社の入力補助＋自由入力、担当者・連絡先編集を追加。工事・提出物の適用条件、独立した疎通試験完了日、受電・送電の同日扱い、供給開始希望日／開始日、事業者変更の両側完了日からNo.93を表示。
6. **商用運転**：No.96〜98を削除。回覧板配信・Excel添付名、EMS試験結果共有日を維持。JEPXは太陽光で対象外。EPRX参入日を参入資料提出日より後、最後の入力項目として配置。
7. **履歴・タスク**：任意メモ、複数タスク・対応期限・完了、対象外と未入力（対象外は警告・見込計算から除外）、仮の30日アラート、再接続検討の画面内確認と旧申請退避、添付名を実装。iframeはモーダルを許可しないため、`window.confirm` に依存しない。
8. **一覧・集計**：案件データから現在工程と業務状況を算出し、仮工程順で降順に並べ替え。回答待ち・支払待ち・証憑未送付・期限超過は重複該当ありと明記。

## 保存範囲

値・添付名・タスク・履歴は案件ごとにJavaScriptメモリへ保持。再読み込みすると初期サンプルに戻る。ファイル本体、外部連携、メール送信、サーバー保存は実装しない。再接続検討は接続検討と地位移転／エコ革名義要否確認を旧申請回に退避し、共通情報・設備・本申込以降を保持する設計案。

## 検証

`python3 tests/power_mock_smoke.py` で、Python標準HTTPサーバーと実Chromiumを起動して検証。Python Playwrightと `/usr/bin/chromium` が必要。スクリーンショットと実行結果JSONは既定で `/tmp/ecokaku-power-review/`、`ECOKAKU_REVIEW_DIR` で変更可能。

- 6タブ、案件別保存、整数・選択肢・キュービクル複数行、アグリゲーター履歴。
- 段階別連系見込、予定／実績、起算日不足、2028年1月31日→2月29日、2027年1月31日→2月28日、遅い日採用、更新履歴。
- 請求額を上書きしないこと、経理参照が編集欄でないこと、証憑送付後の集計更新。
- 地点番号の一致／不一致／未入力、先頭ゼロ、5桁を超える系統コード。
- 両側申請だけでは完了しないこと、両側完了、電力会社別適用、疎通試験の独立管理、新設日付。
- 添付名・タスク・履歴の案件分離、削除項目・EPRX名称／順序、太陽光／蓄電池のJEPX適用。
- 再接続検討のキャンセル／確認／退避と他工程の保持。
- 一覧と工程グラフの件数一致、並べ替え、共通マスタの反映。
- 営業の契約日保存、法務の契約番号更新と営業への共有、設定の利用者追加。
- デスクトップ・モバイル表示、再読み込みによる初期化、未処理JS例外・外部リソース失敗の有無。
