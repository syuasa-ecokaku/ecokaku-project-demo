# トップダッシュボード改修レビュー

対象は `index.html` の iframe `#codex-visualization` に埋め込まれたトップ画面のみ。作業開始点は `49ed427`（全7部門のサマリーカード統一を含む）。各部門画面・既存案件・保存方式は維持する。

## 画面と実装

- 初期表示は蓄電池／稼働中案件。3事業を切り替えるとKPI、一覧、4グラフが更新され、選択KPIは稼働中へ戻る。
- 3つの等幅KPIカードはボタンとしてクリック・キーボード操作に対応。矢印、ホバー背景、選択枠を表示する。
- KPI直下の一覧を1つの領域で切り替える。最大5件と全件表示を切り替え、金額合計は常に全案件分を表示する。
- ドーナツ、7部門の横棒、請求・入金、週別予定を2列×2段で表示する。狭い幅では縦並びと表の横スクロールを使用する。
- 個人タスクのKPI・チェックリストと、旧最下部の重複案件一覧を削除した。部門側のタスク操作と既存データは保持する。
- `homeBusinessCases` / `homeDepartmentInfo` / `homeInvoices` / `homeCalendar` は保存済みデータを読み取るアダプター。`homeProjection` の同じ集計結果をKPI・一覧・グラフへ渡す。
- CSSは `#sales-demo-home` 内に限定する。外部ライブラリ、通信、保存先は追加していない。

## 集計定義

| KPI | 定義・参照元 | 初期データでの表示 |
| --- | --- | --- |
| 稼働中の案件 | 案件全体の明示的な完了・中止・廃止を除く。部門単位の完了は除外しない。「稼働」は管理継続中の意味。蓄電池の正式区分は既存の正式承認情報を参照する。 | 蓄電池10件（仮8／正式2）、太陽光6件、データセンター0件 |
| 今月の連系予定 | 電力申請 `powerForecast` の採用見込日が基準月内。受電・送電実績No.89が登録済みの案件と終了案件を除く。 | 蓄電池1件：P-00002、2026-11-27 |
| 発行済請求の残額 | 既存の営業請求明細 `rows` の発行済みのみを対象とし、明細ごとに請求額−入金額を計算して案件に合算。同じ案件＋明細キーの重複、取消済み、未発行を除外する。 | 太陽光9,166,667円（発行済27,500,000円−入金済18,333,333円）、蓄電池・データセンターは未設定 |

デモ基準日は既存の `departmentDemoDate`（2026-11-04）で、画面上に明示する。月集計はこの年月に揃える。太陽光の電力会社の見込は未登録であり、連系予定KPIの0件にその旨を併記する。旧トップにあった社内連系予定は週別予定の参考情報として残し、電力会社の見込に混ぜない。

ドーナツは1案件を1つの主担当工程へ分類し、合計を稼働中案件数と一致させる。主担当は既存の工程・実績・承認状態から表示用に判断し、元データに書き戻さない。構成比は端数調整して計100％とする。部門別の要対応件数は既存の状態・期限・引継ぎ事項を案件単位で集計し、対象工程前は除外する。同一案件が複数部門に該当できるため、7部門の合計は稼働中件数とは異なる。

週別予定は既存の予定日・期限だけを使用し、月初から7日ごとに全日を集計する。予定種別を色分けし、週ボタンで該当案件を表示する。

## 画面遷移と保存範囲

- 案件番号・案件名から、事業と案件IDを指定して部門の案件詳細を開く。
- 連系予定からは該当する電力申請の連系・受電セクション、請求残額からは営業の請求・入金詳細へ移動する。
- 太陽光の既存トップ専用サンプルで部門別レコードがない場合は、トップ内で既存情報の参照表示を開き、部門詳細が未登録であることを表示する。部門レコードを生成しない。
- 部門で保存した値はトップに戻った際の集計へ反映する。未保存の下書きは集計に含めない。
- 既存の画面内保存を維持し、再読み込みすると初期デモデータへ戻る。サーバー保存・部門間共有は実装していない。

## 検証

`tests/executive_dashboard_smoke.py` はChromiumで以下を検証する。

- 3事業と3KPIの切替、初期値、等幅カード、キーボード操作、一覧の5件／全件切替。
- KPI・一覧・ドーナツ・請求グラフの一致、連系見込保存後の再集計、再読み込み時の初期化。
- 正しい事業・案件・部門への遷移、未登録詳細の参照表示、週別予定の切替。
- テスト専用データによる請求重複・取消・未発行の除外、案件全体の終了除外、6件の金額一覧を折りたたんでも全件合計を維持。
- 開始点 `49ed427` と全7部門×3事業×3タブの63画面のテキスト・入力値・選択肢を比較。既存の共通データ定義、ヘッダーも照合する。
- 狭い幅でのレイアウト、JavaScriptエラー・リソース失敗・外部書き込みがないこと。

既存回帰テストのうち、旧トップの削除済み要素を検査していた3箇所を新トップの集計確認へ変更した。部門操作の検査は維持する。
