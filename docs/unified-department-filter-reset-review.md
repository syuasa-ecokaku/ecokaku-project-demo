# 全7部門の絞り込み解除の一本化

作業ブランチ: `feat/unified-department-filter-reset`。開始コミット: `3e1405b`。適用対象のAGENTS.mdなし。既存の未追跡 `.agents/` を保持。mainへのマージ・本番公開は行わない。

## 変更内容

共通の `departmentFilterHTML` から、KPI選択中だけ下段に追加される「KPIの絞り込みを解除」を描画処理ごと削除。非表示CSSで隠す方式ではなく、同等の別名ボタンや空のラッパーも作らない。上段の検索エリア右側にある「絞り込みを解除」だけを使用する。

不動産開発・営業・法務・購買・工事・メンテナンスは、既存の共通解除処理で案件番号／名称・キーワード・担当者・進捗・期限・KPI条件を解除し、並べ替えを初期の案件番号順にする。営業の旧画面も同じ解除ボタンから既存営業ステータス・KPI条件を解除する。もともと存在しなかった無効な項目の「未設定」はそのまま保持し、「すべて」や0件等へ偽装しない。

電力申請は解除処理を修正し、以下をまとめて初期化する。

- 案件検索、担当者、現在工程、設備区分、KPI条件。
- 蓄電池サマリーの仲介者・電圧別設備種別・キーワード。
- データ入力の独立した現在工程条件。
- 並べ替えを従来の初期値「進捗順（仮ルール）」へ戻す。

電力申請のKPI状態は、明示的に「全件」カードを選んだ空文字と、解除後の選択なし `null` を区別する。両方とも全件集計だが、解除後は「全件」カードを含め選択枠を残さない。サマリー・データ入力のどちらから解除しても、同じ蓄電池事業の別タブに残った非表示条件をクリアする。解除後も元のボタンへフォーカスを戻す。

部門・事業種別・表示タブ・入力区分・業務工程の列選択は維持する。他事業の検索状態、入力中の案件データ、未保存の下書きは消さず、保存や取消も実行しない。件数・一覧・KPIは既存の集計範囲で再描画する。
