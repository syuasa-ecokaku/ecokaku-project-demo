# 電力申請：新規案件起案・基本設備情報

## 確認する場所

1. 電力申請 → 任意の事業 → **新規案件起案**。
2. 起案区分を選択し、既存の必須項目（仮案件名、主担当者、都道府県、市区町村）を入力。その他の追加項目は任意です。
3. 登録すると従来どおりG番号を自動発行し、案件詳細を開きます。
4. 蓄電池のデータ入力では、工程選択の **基本情報・設備** を選びます。案件詳細では既存の **基本情報・設備仕様** 内の「起案・基本設備情報」で同じ値を編集できます。
5. 太陽光／データセンターのデータ入力には「基本情報・設備」を表示します。詳細な申請工程は従来どおり未定義で、蓄電池の工程を複製していません。

型式・台数は一覧／詳細の「設備明細を編集」から共通の補助画面を開きます。**入力内容を適用**すると親画面の下書きに入り、親の保存・取消に従います。補助画面のキャンセルは補助画面の編集だけを取り消します。型式はマスター登録を前提としないテキスト入力です。

## 起案フォーム

既存の2列・狭幅1列・本文スクロール・ヘッダー／フッターを使用し、次の順に整理しています。

- 起案・基本情報：起案区分、事業種別、仮案件名、主担当者。
- 所在地・土地情報：都道府県、市区町村、町名・地番、地目、地類。
- 申請・設備情報：名義、AC容量、該当するDC容量、蓄電池／PCSの複数型式・台数。
- 関係者・補足：仲介者・紹介元、備考、関連資料。
- 登録情報：起案者、起案日、登録時に自動発行する案件番号。

起案区分は「新規案件／EPC案件／権利譲渡案件／申請依頼案件」の4択で、初期状態は未選択・起案時必須です。名義は申請に使う法人名・個人名であり、主担当者・起案者・営業の顧客とは別に保持します。

## 単位と入力検証

| 項目 | 保存する意味・検証 |
| --- | --- |
| AC容量 | kW。空欄を保持し、入力時は0より大きい有限数。小数可。 |
| 蓄電池のDC容量 | DC蓄電容量・kWh。空欄または正の有限数。 |
| 太陽光のDC容量 | DC設備容量・kW。空欄または正の有限数。蓄電池とは別の保存先。 |
| データセンターのDC容量 | 定義を追加せず非表示・保存対象外。 |
| 蓄電池型式・PCS型式 | それぞれ複数行。型式と正の整数の台数を別々に保存。完全な空行は除外。片方だけの入力はエラー。 |
| 地目・地類 | 独立した「未選択／その他」。その他の自由入力をそれぞれ保持。選択肢は確認中。 |

起案フォームでは事業を切り替えても両方のDC入力を消しません。元の事業に戻すと復元します。登録するのは選択中の事業に適用されるDC容量だけです。データセンター登録時にはどちらのDC容量も保存しません。kW／kWhの変換、型式別容量の推測、容量合計の自動計算、地目から地類への変換は行いません。

既存案件の追加項目は未登録です。既存の最新申請値（No.14・15）をAC・DC容量へ自動補完しません。最新申請値と今回の起案・基本設備情報は意味を区別します。旧形式の単一型式・台数（No.17～20）は値を消さず、詳細の折りたたみ内に参照表示します。新しい複数行への推測による移行は行いません。

## 保存・データ構造

新しい値は案件と同じ `source.power.intake` に保存し、起案・一覧入力・詳細・設備補助画面で参照します。別の案件台帳やマスターを作成していません。

| 保存キー | 内容 |
| --- | --- |
| `caseType` | 案件の種類。採番元 `source.origin` とは独立。 |
| `applicantName` | 名義 |
| `acCapacityKw` | AC容量・数値または空文字 |
| `batteryCapacityKwh` | 蓄電池事業だけに保存するDC蓄電容量 |
| `solarCapacityKw` | 太陽光事業だけに保存するDC設備容量 |
| `batteryModels` / `pcsModels` | 別々の配列。各行は固定行ID・型式・台数を保持。 |
| `landDesignation` / `landDesignationOther` | 地目とその他の内容 |
| `landClassification` / `landClassificationOther` | 地類とその他の内容 |

既存の `powerBusinessStores` の下書きとブラウザー保存トランザクションを利用します。保存済み情報は同じブラウザー・URL内で再読み込み後も復元し、既存の案件・発注・顧客マスター・承認・履歴を初期化しません。保存失敗時は案件・番号・設備情報を戻し、入力を保持します。太陽光／データセンターの従来の申請確定日と追加項目も、互いの下書きを消さず同じ案件へ保存します。

下書きは画面・入力区分・事業の切替後も保持しますが、保存前の再読み込みでは復元しません。関連資料は従来どおりファイル名だけで、本体は保存・送信しません。

## 変更しない採番・正式化

電力申請からの起案は `origin: power` のままでG番号、不動産開発からの起案は従来フォーム・`origin: realestate`・R番号です。案件の種類によって番号系列を変更しません。キャンセル・入力エラー・保存失敗では番号を消費しません。

案件名・所在地による候補表示、既存案件を開く操作、別案件として起案するための確認を維持します。正式化条件、既存承認、P番号、変更登録の枝番・履歴、他部門の入力方式は変更していません。通常保存で枝番は増えません。

## 動作確認

`python tests/power_initiation_details_smoke.py` で、起案区分4種類、追加項目の空欄、正の小数・不正値、単位別保存、事業切替、複数型式・空行・片側入力、地目／地類、一覧／詳細／補助画面、保存・取消・再読み込み、候補・G/R採番・保存失敗・狭幅を確認します。結果・画面は `/tmp/ecokaku-power-initiation/`。

既存の案件起案・変更・正式化・承認・複数タブ競合、電力申請の連続入力・既存工程、購買業務についても回帰確認します。ブラウザーテストの一部は、実行環境の証明書を信頼するPython HTTPSクライアント経由で既存の固定CDNスクリプトを読み込みます。TLS検証は無効にせず、製品コードやCDN URLは変更しません。

## 部門への確認事項

- 地目・地類の正式な選択肢と意味・適用範囲。
- 旧単一型式から新しい複数行形式へ移す場合の対応確認。
- 起案・基本設備容量と、電力会社へ提出する最新申請値の転記・確定運用。

いずれも未合意の自動変換・転記・初期補完は追加していません。公開モックへ実在する個人情報・取引情報は追加していません。
