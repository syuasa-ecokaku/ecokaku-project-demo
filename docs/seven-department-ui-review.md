- `departmentSection` / `departmentDetailHTML`：案件基本情報、部門業務、進捗、書類、対応履歴、変更履歴。営業も同じ6区分の内側に既存機能を保持。

## データ・保存

- `departmentConfigs`：部門別の列・型・選択肢・KPI・予定・対象事業・サンプル。業務ロジックを画面共通化と分離。
- `departmentStores[部門]`：案件別の値、下書き、編集開始時の値、形式エラー、添付名、対応／変更履歴。部門間で独立。
- 検索・担当者・状態・期限・ソート・選択案件は事業別に保持。入力区分、開閉状態も維持。事業・タブ・絞り込みで下書きを消さない。
- 保存・取消はその部門の非表示案件・事業・入力区分の下書きも対象。他部門の下書きを保存・取消しない。
- 保存前に数値・日付を検証。エラー時はすべての下書きを保持。
- 既存の営業／法務の契約データは同じ共通オブジェクトを利用。工事の既存P案件の完工・検収・引渡し予定も既存共通値を参照・更新。その他の部門固有値は独立。共有値が編集中に他画面で変わった場合は競合を表示して保存を止める。
- メンテナンスは案件→設備配列→点検／障害記録を分離。点検保存時に案件・設備に紐づく点検記録IDを作成し、既存記録を保持。今回の表入力は代表設備が対象。
- 保存はメモリー内のみ。再読み込みで初期化。添付はファイル名のみで、サーバー保存済みとは表示しない。外部メール・通知・アップロード・連携は実行しない。
