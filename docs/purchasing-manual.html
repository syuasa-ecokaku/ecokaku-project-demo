基本操作：入力・保存・数量の反映

通常の入力は一覧で行います。補助画面の内容も、同じ未保存・保存ルールに従います。

  1. 事業（蓄電池／太陽光／データセンター）を選び、データ入力を開きます。
  2. 検索・絞り込みを設定し、入力区分を選びます。
  3. セルを直接編集します。黄色＝未保存、赤色＝入力エラーです。Tab／Shift＋Tabで隣のセルへ移動します。
  4. 変更をまとめて保存を押し、保存メッセージを確認します。取り消す場合は未保存の変更を取り消すを押します。

保存・取消の範囲

選択事業の全入力区分・非表示行が対象です。他事業の未保存変更は含みません。

区分・タブ・事業を切り替えても編集は保持。保存前にページを再読み込みすると、未保存の編集は復元されません。

保存済みデータは同じブラウザー・同じURLで復元します。別端末・別ブラウザーとは共有しません。

入庫・引当・出庫・引当解除・移管完了の場合

発注・明細・請求・支払予定の通常入力は「まとめて保存」で台帳へ反映します。新規発注や追加明細は、②で別途「発注を確定／追加明細を確定」を行います。

①②　購入準備と発注条件を分けて入力

①は何を買うか、②は価格・納期・納品先などの条件を決めて発注する区分です。

① 購入内容・発注準備

  1. 発注を追加を押します。新規発注行が未保存へ追加されます。
  2. 購入区分・仕入先・担当者・備考を入力。初期値は在庫向けです。案件向けにする場合は購入区分を変更します。
  3. 明細を追加を開き、製品・型番・数量・単位・明細区分・使用案件を入力します。
  4. 親画面の未保存へ追加で一覧に戻ります。製品や送料が複数ある場合は繰り返します。単価・納品条件は②で入力します。
  5. 変更をまとめて保存で購入準備を保存します。

② 発注・納期確認

  1. ①の条件を②で入力、または入力区分の② 発注・納期確認を選びます。
  2. 発注番号・発注日・支払条件を設定し、明細ごとの単価・税・納期・納品方法・場所・予定荷受人を確認します。
  3. 仕入先・製品・数量などは参照表示です。変更が必要なら購入内容を①で変更から戻ります。
  4. 変更をまとめて保存の後、発注を確定を押し、確認画面でも確定します。
  5. 業務状態と、登録した発注・明細・合計額を確認します。
入力するときの判断この画面での扱い
案件が未定在庫向けを選び、明細の使用案件は未指定で登録。架空の案件番号は作りません。
送料・保管費費用明細として登録。在庫数量には加算しません。
現場直送①で使用案件、②で現場直送・納品先を指定。④の倉庫入出庫は省略します。
確定済発注の内容変更一覧の変更理由を入力して保存。実績のある明細は変更できる項目が制限されます。

「発注を確定」はモック内の状態を確定する操作です。仕入先への発注書送信は行いません。確定した発注残も、受領するまでは実在庫に加算されません。

③　分納・荷受確認と入庫

倉庫への受領と入庫は、同じ一つの記録です。別画面で入庫をもう一度登録しません。

  1. 入力区分③ 納品・荷受確認を開き、対象の発注・明細を探します。
  2. 納品を追加を開き、今回の受領数量・実績日・使用不可数・実際の荷受人・不足／破損等の確認内容を入力します。
  3. 親画面の未保存へ追加 → 親画面で変更をまとめて保存。ここでは「準備」が保存され、数量はまだ変わりません。
  4. 準備行の入庫・受領を登録を押します。増減を確認し、数量への影響を確認して実行を押します。
  5. 累計受領・未納・倉庫在庫と履歴を確認。分納の次回も同じ明細へ追加します。
例：発注001のパネルを2枚受領
発注12枚・受領済4枚・未納8枚
↓ 今回2枚を実行
受領済6枚・未納6枚・倉庫実在庫6枚
現場直送
受領実績として記録しますが、倉庫在庫は増えません。④の倉庫出庫を追加する必要はありません。
受領数・荷受情報
受領数量は未納残以下、使用不可数は今回受領数以下が必要です。予定荷受人と実際の荷受人は別の情報です。

初期サンプルの数値を使った例です。操作済みの環境では、画面の現在数量から確認してください。過去実績の荷受人・確認内容が未記録の場合、予定値から自動で補いません。

④　在庫の引当・出庫・履歴

使用予定は「見込み」、確定引当は「確保した数量」です。二つを分けて扱います。

案件に引き当てる

  1. ④で製品・型番・保管場所・利用可能数を確認します。
  2. 案件に引き当てる → 対象案件・数量を入力。
  3. 親画面の未保存へ追加 → 変更をまとめて保存。
  4. 準備行の引当を確定 → 数量への影響を確認して実行します。

引当済のものを出庫する

  1. 対象の確定引当行で出庫を追加を押します。
  2. 出庫日・出庫数量・担当者・備考を入力します。
  3. 未保存へ追加 → まとめて保存 → 準備行の出庫を登録。
  4. 数量への影響を確認して実行し、実在庫と引当残の両方が減ったことを確認します。
発注002・杭の例実在庫使用不可引当残利用可能
初期状態（入庫20本、既に4本出庫）16本2本6本8本
追加で3本を引当16本2本9本5本
その引当から2本を出庫14本2本7本5本
計算式
利用可能＝実在庫－使用不可－引当残
未入庫の発注残は、実在庫へ足しません。
使用予定・引当解除
「使用予定を追加」は数量を確保しません。引当解除も、準備を保存してから実行します。
元の発注を調べる
入出庫履歴の元入庫・発注明細から、どの発注のものを使ったか確認できます。

在庫は製品・型番・保管場所単位の共通残です。案件フィルターは使用予定・引当・出庫へ適用し、共通在庫自体を案件別に按分しません。異なる製品・単位の数量を足し合わせて確認しないでください。

⑥　案件間移管・倉庫間移管

案件間は使用先の変更、倉庫間は保管場所の変更です。完了するまで数量を反映しません。

移管を申請・確認する

  1. ⑥で移管を追加を開き、区分・製品・数量・移管元/先の案件と場所・申請日・予定日・依頼者・担当者・理由を入力します。
  2. 未保存へ追加 → 変更をまとめて保存。申請中の移管記録になります。
  3. 内容を確認し、一覧の状況を確認済へ変更 → 変更をまとめて保存。

移管を完了する

  1. 確認済の行で移管完了を準備を押し、完了日を入力します。
  2. 未保存へ追加 → 変更をまとめて保存。この時点でも在庫は変わりません。
  3. 準備行の移管を完了 → 数量への影響を確認して実行を押し、移管元・先と履歴を確認します。
区分何が変わるか確認すること
案件間移管確定した引当の案件を変更。保管場所が同じ場合もあります。6ページの例から2本を案件A→Bへ移すと、実在庫14本・引当合計7本は変わらず、案件A5本／B2本になります。
倉庫間移管元倉庫を減らし、先倉庫を増やします。通信装置4台のうち1台を第一→第二倉庫へ移すと、第一3台／第二1台。全社合計4台は同じです。

移管で仕入先への支払予定は作りません。移管可能数は申請・完了時に検証します。完了済の再反映は不可。未完了の数量・元/先等を変更するときは、変更理由を入力し保存します。

⑤　請求確認・前払／残金の支払予定

購買が把握する予定と確認を扱います。納品前でもこの区分へ直接移動できます。

条件から支払予定を作る

  1. ②の支払条件を確認し、⑤で対象発注の条件から予定を作成・更新を押します。
  2. 補助画面で条件を確認 → 親画面の未保存へ追加 → 変更をまとめて保存。
  3. 予定日・予定額・根拠・購買確認を確認します。追加や修正も一覧から保存します。
  4. 同じ操作を繰り返しても、自動予定は同じIDを更新します。手入力の追加予定は別に残るため差額を確認します。

請求書を確認して紐づける

  1. 請求を追加で請求書番号・請求日・受領日・金額・対象明細・購買確認を入力します。
  2. 未保存へ追加 → 変更をまとめて保存。資料はファイル名のみ保存します。
  3. 支払予定行の対象請求を選び、必要に応じて根拠を請求書確認へ変更して保存します。
  4. 「請求書確認」を根拠にする場合は、確認済の請求が必要です。紐づけ自体で予定額は増えません。

データ構成図：同じ記録を各画面で使う

実装済みモックの論理構成です。サーバー上のデータベースを新設した図ではありません。

発注と明細

1案件に複数の発注、1発注に複数の明細を持てます。案件との関連は明細ごと。在庫向けは案件未指定可。行番号や住所で紐づけません。

受領から在庫の使用へ

一つの明細へ複数回の受領を登録。引当・出庫・移管には、元入庫IDと配分数量を保持し、元の明細・発注へ遡れます。

請求と支払予定

1発注に複数の請求・予定。1予定の対象請求は未指定可。請求書が届いたら既存予定に紐づけ、予定を重ねて作りません。

在庫残は実績から計算する表示
実在庫＝倉庫入庫－出庫±完了移管
利用可能＝実在庫－使用不可－引当残。独立した在庫残を各画面で手入力する構成ではありません。
図の外にある「入力の準備」
編集中の値は事業別の未保存バッファに保持。数量操作の準備は保存されても実績に数えません。実行時に実績へ反映します。使用予定も確定引当とは別です。

図の破線は任意の紐づけ・更新関係です。このモックの請求は一つの発注の範囲で対象明細を指定します。複数発注をまとめた請求や案件別の金額按分は未対応です。

確認のしかた・困ったとき

初めて操作する場合は、発注001と002を使って次の順に確認してください。

確認すること手順・判定
□ 複数明細と送料①②で発注001を確認。製品と費用を分けて管理できている。
□ 分納と直送③で一部受領。累計・未納が更新され、直送分は倉庫在庫を増やさない。
□ 案件未指定の購入①で在庫向けを作り、案件未指定のまま発注・入庫できる。
□ 引当・出庫・移管④⑥で準備を保存しただけでは数量不変。実行後に実在庫・引当・場所/案件が整合する。
□ 前払・残金・請求③の完了前に⑤を登録できる。条件再作成や請求紐づけで予定が二重にならない。

画面に出ない／保存できないとき

  • 対象が出ない場合はすべてを選ぶか、絞り込みを解除します。「案件未指定」は本当に未指定の対象だけです。
  • 赤いセルとエラー文を確認して修正し、再度保存します。数量不足・未納超過・未来の実績日などは実行できません。
  • 実行前に未保存の変更がある場合は、まず同じ事業の保存または取消を行います。
  • 保存容量不足や他画面との更新競合は、画面のエラーに従って確認します。保存成功のメッセージを確認してください。

確認しておきたい仮設定・制約

  • 数量と単価は整数、税額は明細ごと切捨て。
  • 元入庫はFIFO、旧実績の対応はFIFO推定。移管確認は担当者1段階。
  • 営業日計算、外貨、返品、実績数量の訂正/削除、使用不可品の復旧/廃棄、前払精算は未対応。
  • 初期化は補足・確認用メニュー内。全事業の購買の保存済み・未保存データが失われるため、内容を確認して実行します。

本書は画面確認用モックの操作資料です。正式運用の承認者・税端数・分納時の支払基準・使用不可品の処理は購買部門との確認事項です。確認対象：購買の①②整理版（2026-11-11）。
