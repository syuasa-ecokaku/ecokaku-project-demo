# 共通お知らせカードの1行リスト化

## 作業開始・対象

開始ブランチは `feat/department-kpi-card-design`、HEAD `f816545`。リモートmainと一致し、追跡ファイルの未コミット変更・AGENTS.mdはなかった。既存の未追跡 `.agents/` を保持。作業ブランチは `feat/compact-department-notices`。

実表示は `index.html` の iframe `data-srcdoc` 内。共通の `noticeCenter` の表示・モーダル・復帰処理と `.nc-*` CSSを変更した。不動産・電力申請・営業・法務・購買・工事の18サマリー、および同じコンポーネントを使うメンテナンス3サマリーに適用する。KPI、業務入力・集計、全社トップは変更しない。

## コンパクト表示

- 通知1件を高さ42pxのボタン1つで表示。丸印→カテゴリー→件名→状態→日時→矢印の順。行のどこからでも詳細が開き、Tab・Enter・Spaceで操作できる。
- 件名だけが残り幅を利用し、1行の省略記号と全文ツールチップを表示する。案件番号は必要な場合に先頭へ1回だけ付ける。
- 未読の丸と太字、既読になっても変わらないカテゴリー色、白背景・罫線・ホバー背景・フォーカス枠を維持する。
- 状態は緊急を優先し、それ以外は関連業務の要対応・要承認・対応済み・参考を表示。広幅では期限間近も補助タグで表示し、狭幅では主要状態だけにする。詳細には全状態を表示する。
- 本文・詳細種別・案件名・発信部門・対応期限・補足は通常行から除き、詳細に集約。「詳細を開く」の独立リンクは廃止する。
- 見出し・未読数・すべて見る、カテゴリー・未読／要対応の2段構成。通常は最大5件で、カード内に縦スクロールを設けない。少件数・空状態は内容に合わせて縮む。
- 「すべて見る」は同じカテゴリー・フィルターの全件モーダル。モーダル自体をスクロールし、行領域の中に別のスクロールを作らない。
- 1000px以下は一覧日時を日付だけにし、650px以下では非表示。どの幅でも通知行は1行を維持し、正確な日時は詳細で確認できる。

## 詳細と復帰

- カテゴリー、詳細種別、優先度、全文、事業、案件番号・案件名、発信部門、秒と日本時間を含む通知日時、対応期限、対応状態を表示する。
- 実在する関連画面が登録された案件にだけ「該当案件を開く」または「承認情報を開く」を表示。案件と無関係な全社共有にはボタンを表示しない。
- 未実装・未登録・閲覧対象外の遷移先は操作ボタンを表示せず、説明だけを表示する。通知から承認や業務完了を実行する機能は追加しない。
- 詳細を開いた時点でその利用者の既読にし、要対応・承認待ちはそのまま。一覧・情報画面・フィルター・再描画では既読にしない。
- 部門・事業・フィルターと、iframe内・外側ページのスクロール位置を保持する。閉じるボタン・Escで元の通知行へフォーカスを戻す。
- 未読フィルター等により読んだ行が対象外になった場合は、フィルターを変更せず、近くの残った行へ戻す。行が0件になった場合は選択中のカテゴリーボタンへ戻す。
- 全件一覧から詳細へ進んだ場合は、一覧へ戻ると一覧のスクロール位置と選択行を復元する。関連業務画面へ遷移するときは、元画面のスクロール復元を実行して遷移先を上書きしない。

## デモ説明・既存処理

カード下部の説明と閲覧者切替を、見出し横の小さな情報ボタンへ移動した。情報モーダルに閲覧者切替、フロント側のデモ権限制御であること、既存の基準日、画面内保存・再読み込みでの初期化、実送信なし、既読と対応済みの区別を残す。

通知データ、対象者・ロール・案件範囲、カテゴリー・ANDフィルター、並び順、イベント生成・重複防止、既読・業務状態、保存方式は維持する。`visible`、`related`、`list`、`rank`、`emit`、`snapshot`、`publishChanges`、`transactionAround`、`seed` の処理は開始点と一致する。localStorage、サーバー保存、実プッシュ・メール・外部通知は追加しない。
